
<REPO_DIR> devcontainer control.   Backend follows the active docker context.

Engines                           the two backends a target can act on:
                          local   this machine's engine; builds bind-mount this folder
                          remote  an EC2 engine; the repo is cloned into a volume on it

Scope                             the second column of every row:
                          both    works on either engine via the active context
                          local   that engine only
                          remote  that engine only
                          host    runs on this machine and touches no engine at all

TARGET                    SCOPE   WHAT IT DOES

START HERE
  make up                 both    Get working from any state: refreshes the tunnel (remote), builds or starts as needed, then opens VS Code.

FIRST RUN                         once per machine
  make init               host    Create the gitignored config files (incl. the hostcreds manifest) from their examples. Never overwrites an existing one.
  make keybindings        host    Bind Shift+Enter to a newline in VS Code terminals. Must run on the host, not in the container.

ENGINE                            pick where builds and containers live
  make local              host    Point docker and VS Code at the local engine (<LOCAL_DOCKER_CONTEXT>). Nothing remote is stopped.
  make disconnect         host    What 'make local' calls. Only changes where new commands and windows point.

INSTANCES                         one remote engine per project under remote-instances/; instance names are project names (e.g. acme)
  make list-instances     host    List every instance with live status: EC2 state, id, params, certs, forward, context; ssh engines answer reachability instead.
  make list-containers    host    Every container this project owns, local engine plus every instance's, with per-engine reachability.
  make instance-init      host    Scaffolds <project>; never deploys. INSTANCE=<n> [AMI=] [REGION= AMI/AZ lookup; deploys in REMOTE_AWS_REGION]. Azure: CLOUD=azure LOCATION=<loc> GCP: CLOUD=gcp PROJECT=<p> ZONE=<z>
  make instance-deploy    remote  Converge: provision, record the engine address (EC2 links the id, azure the record), trust chain, push secrets. Refuses replacement without CONFIRM=replace. INSTANCE= | ALL=1
  make instance-status    host    One instance's live state, or every instance with ALL=1. INSTANCE=<instance-name> | ALL=1
  make instance-plan      remote  Terragrunt plan per instance; bootstraps the state bucket (EC2) or ensures the azure state store on first run. INSTANCE=<instance-name> | ALL=1
  make instance-stop      remote  Stop the instance's VM (EC2 or azure) and wait until it reports down. INSTANCE=<instance-name> | ALL=1
  make instance-start     remote  Start it again and wait for its engine agent to report ready. INSTANCE=<instance-name> | ALL=1
  make instance-destroy   remote  Destroy + cleanup context, certs (and EC2 params). CONFIRM=destroy only for ALL=1. INSTANCE=<instance-name> | ALL=1
  make instance-link      host    EC2 only: save the instance's EC2 id; deploy does this automatically. Azure has no id: the deploy writes its record. INSTANCE_ID=<id>
  make engine-init        host    Scaffold an ssh engine manifest (engine.json). INSTANCE=<name> HOST=<host> USER=<user> [PORT=22] [DOCKER_ADDR=/var/run/docker.sock; a Windows engine needs tcp://localhost:2375]
  make engine-verify      host    One-shot ssh engine reachability proof: opens the forward, handshakes docker through its context, closes the forward. The ssh engine's connect-start.
  make engine-remove      host    Remove an ssh engine whole: forward, docker context, local state, registration. Needs CONFIRM=remove; refuses while a project container exists on the engine.
  make cert-ca            host    Create this instance's certificate authority. Once per instance; refuses if one exists.
  make cert-client        host    Issue the client certificate 'make connect-start' presents. Run after cert-ca, and again at renewal.
  make cert-publish       remote  Issue server material and publish it to the engine's store (Parameter Store, or Key Vault for azure). The daemon needs it to open its listener.
  make cert-install       remote  Have the instance fetch the published material and start its daemon. Run after cert-publish.
  make cert-status        host    Client and CA expiry per instance. Remote engines only (EC2 and azure); ssh engines carry no TLS material.
  make push-secrets       remote  Publish shell.env and aws-profile-map.json to the engine's store (Parameter Store, or Key Vault for azure). Remote builds do this when needed.
  make connect-start      remote  Open an engine's forward as a background daemon (SSM for EC2, ssh for engine.json, relay for azure, iap for gcp); returns once docker answers. INSTANCE=<name> (or ENGINE=<name>).
  make connect-status     host    Forward daemon state per instance: pid, port, listening. INSTANCE=<name> | ALL=1
  make connect-stop       host    Close one forward daemon, or every one with ALL=1. INSTANCE=<name> | ALL=1
  make connect-refresh    host    Stop and reopen from the recorded command -- for an expired SSO session or a dropped tunnel. INSTANCE=<name> | ALL=1
  make connect-list       host    Every instance's forward: pid, port, listening or not.
  make bucket-list        host    Every state store this fleet's naming template matches (EC2 buckets, azure accounts): name, configured or orphaned. Per kind; mixed fleet refused. EC2 needs REMOTE_AWS_REGION.
  make bucket-delete      host    Purge + delete state stores: INSTANCE=<name> (EC2 bucket or azure account), or ALL=1 CONFIRM=delete for every one. Per kind; mixed fleet refused. EC2 needs REMOTE_AWS_REGION.
  make remote             host    Point them at the remote engine (<REMOTE_DOCKER_CONTEXT>): ensures the engine's forward in the background, then switches docker. INSTANCE=<name> targets that instance.

BUILD                             every target blocks until the container is up and exits non-zero if anything fails
  make build              both    Create the container for the active backend. Refuses if one already exists.
  make rebuild            both    clean, then build. Prerequisites are checked before anything is destroyed.
  make build-no-cache     both    build with the image rebuilt from scratch.
  make rebuild-no-cache   both    rebuild with the image rebuilt from scratch. Use when a feature or base image changed.
  make clean              both    Destroy the container, its private volumes and its image; the image is kept when a sibling still uses it. ALL=1 needs CONFIRM=destroy.

LIFECYCLE
  make status             both    Backend, container, image and volumes. Read-only, so start here. ALL=1 reads every engine, one after the other.
  make reopen             both    Open the container in VS Code. Local opens the folder; remote names the container to attach to.
  make exec               both    Interactive shell inside the container. CONTAINER_SHELL picks which one.
  make vscode-server      both    Fetch the VS Code server this machine needs inside the container. reopen does it for you.
  make start / stop       both    Start or stop the container. The checkout survives either way. ALL=1 for every engine.
  make restart            both    Restart in place. Fixes a wedged container without rebuilding anything. ALL=1 for every engine.
  make rename NAME=x      both    Give the container a readable name. New ones are <repo>-<devcontainerId>, which is too long to pick from a list.
  make check              both    Remote: report uncommitted or unpushed work in the volume, non-zero when dirty. Local: a no-op. ALL=1 for every engine.

SECRETS AND CERTIFICATES
  make push-creds         both    Resolve every hostcreds manifest entry on this machine and push it into the container. Git entries also seed ~/.git-credentials.
  make creds-init         host    Prompt once per missing keychain item the hostcreds manifest names and store it. CREDS_INIT_ARGS='--stdin NAME' feeds one value from stdin.
  make verify-container   both    Check the pushed credentials inside the container: fragment modes, startup block, git and aws reachability.

HOST PROXY                        only needed behind a corporate proxy; remote builds force HOST_PROXY=false
  make proxy-start        local   Run tinyproxy on this machine. Local containers reach it via host.docker.internal.
  make proxy-status       local   Whether it is running, and on which port.
  make proxy-restart      local   Stop then start, picking up changed settings.
  make proxy-stop         local   Stop it. Settings come from .devcontainer/remote-docker/config.env; set HOST_PROXY=true in shell.env to make the container use it.

QUALITY
  make lint               host    Private files untracked, no nested repos, no host venv in the workspace, JSON parses, shellcheck, markdown, US English, prose rules, staged secrets. Non-zero on any finding.
  make lint-secrets       host    Scan staged content for secrets, or RANGE=<a>..<b> for a commit range. Exit 1 on any finding; there is no ignore list.
  make format             host    Auto-fix what the markdown tooling can fix, then report what is left.
  make lint-spell         host    US English spelling over this repo's markdown. SPELL_FILES overrides the set.
  make spell-fix          host    Auto-fix spelling, British-to-American included, in the same set. Rewrites the files.
  make hooks-install      host    Install pre-commit and pre-push hooks via devcontainer_config.githooks. Refuses to clobber a hook it did not write.
  make hooks-run          host    Exactly what pre-commit runs. Use it to reproduce a pre-commit failure.
  make hooks-run-push     host    Exactly what pre-push runs: lint, the pushed-range secrets scan, then the test and coverage steps CI runs.
  make test               host    Run the hermetic pytest suite in tests/. No docker, no AWS, no network.
  make coverage           host    The coverage gate CI runs: the same suite with the 90% floor over devcontainer_config enforced.
  make validate           host    The green-baseline contract automation depends on. Runs lint then test.

SKILLS                            wire this repo's .agents/skills roster into an agent on this Mac; no devcontainer involved
  make skills-install     host    Wire an agent to the skills home: global symlink (default), project verify/wire, or runtime one-shot (printed, never run). AGENT=opencode|claude|both SCOPE=global|project|runtime
  make skills-remove      host    Delete only a general-dev-skills symlink resolving inside this repo; refuses everything else. AGENT=opencode|claude|both SCOPE=global|project|runtime
  make skills-list        host    Show each agent scope: installed (target), native (project), or not installed. AGENT=opencode|claude|both SCOPE=global|project|runtime

OPTIONS
  ENGINE=local|<name>             Address one engine explicitly (ENGINE=x make <target> or make <target> ENGINE=x): drive local and remote engines in parallel; unset follows the active context.
  CONTAINER=<name>                Pick one container when several clones of this repo share an engine. 'make list-containers' lists them.
  NAME=<x>                        Name the container build/up creates at creation; make rename NAME=x does the same after the fact.
  FORCE=1                         Proceed past the unpushed-work and uncommitted-config guards.
  SKIP_SECRETS_CHECK=1            Do not compare shell.env against Parameter Store, and do not publish it.
  NO_CACHE=1                      What the no-cache targets set. Works with build and rebuild directly.

PREREQUISITES

  container targets       docker
  remote engine           aws, session-manager-plugin, and the instance id recorded by instance-deploy (make instance-link)
